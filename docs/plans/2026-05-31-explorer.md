# Block Explorer Plan (`claw-explorer`)

_Plan only — no code yet. Status: 2026-05-31. Owner: TBD._

## What exists

`claw-explorer/` is a **Ping.pub fork** (Vue 3 + Vite). It already ships clawchain
chain configs:
- `claw-explorer/chains/testnet/clawchain.json`
- `claw-explorer/chains/mainnet/clawchain.json`

Both currently point at `localhost` (RPC `:26657`, REST `:1317`), prefix `claw`,
denom `uclaw`/`CLAW` (exp 6), SDK `0.53.6`, features `cosmwasm`/`ibc-transfer`/
`ibc-go`. There's a `Dockerfile` and a `dist/` build; deploy port is **8082** per the
validated Docker setup.

## Goal

A public block explorer per network (devnet/testnet/mainnet) showing blocks, txs,
validators, governance, IBC, CosmWasm contracts, and the custom modules — wired to
the real endpoints, branded, and deployed.

## Steps

### E1 — Chain configs (per network)
1. Update `chains/testnet/clawchain.json` and `chains/mainnet/clawchain.json` with the
   **public** RPC/REST/gRPC endpoints (TLS), correct `chain_name`/`chain_id`
   (`clawchain-testnet-1`, `clawchain-1`), seeds, and `min_tx_fee`.
2. Add a `chains/devnet/clawchain.json` (or keep localhost in testnet for dev) so the
   devnet plan can point the explorer at a local node.
3. Assets/branding: add `public/logos/clawchain.svg`, set `theme_color`,
   `coingecko_id` when listed.
4. Confirm `features`/`keplr_features` match the chain (cosmwasm, ibc-transfer,
   ibc-go; add `tokenfactory` if the explorer supports a custom tab).

### E2 — Custom-module surfaces (fork work)
Ping.pub shows standard cosmos modules out of the box. The clawchain custom modules
(privacy, agent, marketplace, oracle, modelregistry, reputation, messaging,
governance) need either:
- minimal: rely on the generic tx/`Any` decoder so custom msgs at least render with
  their `/clawchain.*` type url + fields (requires the explorer to resolve the type
  urls — provide the proto JSON or a type-url→label map);
- richer (phased): dedicated tabs (e.g. oracle exchange rates, privacy tree stats,
  marketplace skills) backed by the REST query endpoints.
Start minimal; add tabs as priorities dictate.

### E3 — Build & deploy
1. Per-network build (`npm run build` with the target network selected), or a runtime
   network switcher (Ping.pub supports multiple chains in one deploy — list devnet/
   testnet/mainnet clawchain entries).
2. Containerize via the existing `claw-explorer/Dockerfile`; serve on **:8082** behind
   the same reverse proxy/TLS as the other public services.
3. Add to the root `docker-compose.yml` for each network profile.

### E4 — Verify
- Against a live node: blocks advance, a known tx (e.g. a tokenfactory create-denom or
  a shield) resolves and renders, validator list + gov proposals show, IBC channels
  page lists `channel-0`.

## Acceptance criteria

- Explorer reachable on `:8082`, pointed at the live (testnet then mainnet) endpoints.
- Standard cosmos data (blocks, txs, validators, gov, IBC) renders correctly.
- Custom-module txs at least decode/render via their type urls (E2 minimal).
- Branding (logo, theme, denom display CLAW/uclaw exp 6) correct.

## Open decisions

- Single multi-network deploy (Ping.pub switcher) vs one deploy per network.
- How far to go on custom-module tabs in v1 (recommend: ship minimal, iterate).

## Dependencies / references

- `claw-explorer/chains/{testnet,mainnet}/clawchain.json`, `claw-explorer/Dockerfile`
- Testnet/mainnet launch plans (endpoints come from there).
- Custom-module REST query paths (e.g. `/clawchain/privacy/v1/tree_stats`,
  `/clawchain/oracle/v1beta1/...`).
